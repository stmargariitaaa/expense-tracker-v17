## Безпека: перевірка застосунку

### Знайдені вразливості та ризики

| № | Проблема | Тип | Статус |
|---|---|---|---|
| 1 | Поле «Категорія» приймає довільний рядок. Якщо виводити його як HTML (`v-html`, `innerHTML`), введений `<img src=x onerror="alert('XSS')">` виконується в браузері | Stored XSS (зберігається в IndexedDB, спрацьовує при кожному відкритті списку) | Виправлено |
| 2 | Суми й категорії операцій зберігаються в localStorage та IndexedDB у відкритому вигляді; XSS міг би їх зчитати | Витік фінансових даних | Знижено (див. нижче) |
| 3 | Резервна копія операцій у localStorage дублює дані з IndexedDB | Надлишкове зберігання даних | Задокументовано |

### Як виправлено

- Вивід даних користувача йде лише як текст: інтерполяція Vue `{{ category }}` у шаблоні `ExpenseRow` (`js/vue-app.js`) та `textContent` у `script.js`. Директиви `v-html` і `innerHTML` для даних користувача чи API не використовуються.
- Посилання на категорії будуються як `'#/category/' + encodeURIComponent(category)`, тому спецсимволи кодуються, а схема `javascript:` неможлива.
- Дані з API перед записом у базу проходять перевірку (`createTransaction()` та перевірка типу операції в `js/db.js`).

### Перевірка

1. Вразливість відтворено навмисно (тимчасова заміна на `v-html`): тестовий рядок викликав `alert`.
2. Після виправлення той самий рядок відображається як звичайний текст, `alert` не з'являється.
3. Пошук `innerHTML`, `v-html`, `outerHTML`, `insertAdjacentHTML`, `document.write`, `eval(` показав лише три закоментовані `innerHTML = ''` у `script.js` (без даних користувача).
4. Пошук `api key`, `secret`, `token`, `password`, `bearer`, `authorization` у `.js`, `.html`, `.json` не дав збігів: секретів у коді немає, використано лише публічні API без ключів.

### Чутливість даних у браузері

Застосунок зберігає лише суми, типи, категорії та дати операцій; паролів, токенів і реквізитів карток немає. Дані не зашифровані й не прив'язані до облікового запису. У реальному застосунку їх слід зберігати на сервері за авторизацією.

### Розгортання

Застосунок розгорнуто на Render з HTTPS за замовчуванням: https://<назва>.onrender.com

### Можливі покращення

- Обмеження довжини й набору символів поля `category` на клієнті та сервері.
- Заголовок Content-Security-Policy.
- Subresource Integrity (`integrity` + `crossorigin`) для скрипта Vue з CDN.
- Видалення резервної копії з localStorage після успішної міграції.
